1. Executive Summary & Objective

Legacy regional branch locations (such as Regional Branch North, Regional Branch West, Regional Branch South, and Regional Branch Central) operated on end-of-life (EOL) FortiGate-30E and 50E firewalls running legacy FortiOS 6.2. Upgrading to modern hardware (FortiGate-30G and 50G running FortiOS 7.2 and 7.4) presented severe operational risks: manual re-keying across hundreds of firewall policies, VIPs, and VPN definitions was error-prone, risked human omission, and threatened business-hour blackouts.

The Architectural Objective: Author an automated, deterministic migration engine (generate_migration.ps1) leveraging Abstract Syntax Tree (AST) parsing. The engine parses raw legacy backup files, transforms hardware-dependent interface names (e.g., wan1 → wan, lan4 → a), unbinds factory virtual switches, strips invalid legacy UUIDs, and generates an 11-stage dependency-ordered deployment script.

3. Production PowerShell Automation Code Extracts

3.1 Migration Engine Extract (generate_migration.ps1)

# ==============================================================================
# POWERSHELL AST MIGRATION ENGINE: LEVEL 0 FACTORY TEARDOWN & REBIND
# ==============================================================================

function Generate-Level0-Cleanup {
    [CmdletBinding()]
    param([string]$TargetModel)

    $sb = [System.Text.StringBuilder]::new()
    $sb.AppendLine("# LEVEL 0: FACTORY DEFAULT TEARDOWN") | Out-Null
    $sb.AppendLine("config firewall policy") | Out-Null
    $sb.AppendLine("    delete 1") | Out-Null               # Delete factory allow-all policy
    $sb.AppendLine("end") | Out-Null

    # Unbind physical ports from default software switch
    $sb.AppendLine("config system virtual-switch") | Out-Null
    $sb.AppendLine("    delete lan") | Out-Null             # Release lan1..lan4 ports
    $sb.AppendLine("end") | Out-Null

    $sb.AppendLine("config system interface") | Out-Null
    $sb.AppendLine("    edit fortilink") | Out-Null
    $sb.AppendLine("        set status down") | Out-Null    # Prevent FortiSwitch takeover
    $sb.AppendLine("    next") | Out-Null
    $sb.AppendLine("end") | Out-Null

    return $sb.ToString()
}

3.2 Automated Parity Verification Script (check_addr_parity.ps1)

# ==============================================================================
# AUDIT SCRIPT: VERIFY 100% ADDRESS OBJECT PARITY BETWEEN LEGACY AND NEW CONFIG
# ==============================================================================

param(
    [Parameter(Mandatory=$true)][string]$LegacyConfig,
    [Parameter(Mandatory=$true)][string]$NewConfig
)

$legacyAddrs = Get-Content $LegacyConfig | Select-String 'edit "(.*?)"' | ForEach-Object { $_.Matches.Groups[1].Value }
$newAddrs    = Get-Content $NewConfig    | Select-String 'edit "(.*?)"' | ForEach-Object { $_.Matches.Groups[1].Value }

$missingInNew = $legacyAddrs | Where-Object { $_ -notin $newAddrs }

if ($missingInNew.Count -eq 0) {
    Write-Host "[SUCCESS] 100% Address Object Parity Confirmed. Total Objects: $($newAddrs.Count)" -ForegroundColor Green
} else {
    Write-Error "[FAILURE] Missing $($missingInNew.Count) objects in target configuration: $($missingInNew -join ', ')"
}

4. Forensic Incident Deep-Dive & Remediation

Incident: Factory Virtual Switch Port Lockup on FortiGate-30G (Case 17)

Symptom: Staged Level 1 interface configurations threw CLI errors: Interface lan1 is already in use by virtual-switch lan, causing subsequent IP assignment and policy creation to fail.
Investigation: Discovered that factory FortiOS 7.2 on 30G hardware ships with a virtual switch named lan binding ports lan1 through lan4 together. Interfaces cannot be reassigned or configured individually until the parent virtual switch is deleted.
Remediation: Added Level 0 factory teardown to the PowerShell engine, explicitly purging system virtual-switch lan and deleting factory policy 1 before applying any interface commands.
