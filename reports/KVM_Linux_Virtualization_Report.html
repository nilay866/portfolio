1. Executive Summary & Objective

As enterprise infrastructure expanded across 21 locations, procuring and racking dedicated 1U/2U physical hardware appliances for each supporting service (FortiAnalyzer log collector, Squid caching proxy, Postfix mail gateways, internal DNS) created prohibitive capital expenditure and server rack space saturation. Moreover, running single gigabit NIC uplinks created network throughput bottlenecks during nightly bulk log synchronizations.

The Architectural Objective: Consolidate physical appliances onto high-performance Ubuntu 24.04 LTS bare-metal hypervisors powered by AMD Zen 3 processors. The architecture was designed to:

  • Bond dual 10GbE SFP+ physical interfaces into an IEEE 802.3ad LACP aggregate link (bond0) yielding 20 Gbps full-duplex bandwidth with sub-100ms link failover.
  • Implement a zero-overhead Linux kernel bridge (br0) allowing virtual machines direct, unrouted Layer 2 access to the core corporate management network.
  • Deploy a dedicated FortiAnalyzer VM with 16GB RAM, 4 vCPUs, and 100GB qcow2 disk using VirtIO drivers for line-rate log ingestion.
  • Build a Squid 6.14 caching and forward proxy with dynamic SSL-Bump (HTTPS inspection), utilizing an enterprise Root CA certificate deployed via Active Directory Group Policy Objects (GPO).
  • Deploy an authenticated Postfix 3.6 mail submission relay utilizing Cyrus SASL encryption to securely offload alert notifications to Microsoft 365 Exchange Online.

3. Engineering Role & Responsibilities

  • Physical Server Staging & OS Installation: Installed Ubuntu 24.04 LTS Server on AMD hardware, configured BIOS SR-IOV and nested AMD-V virtualization flags (kvm_amd nested=1).
  • Netplan LACP & Bridging: Authored declarative YAML network configuration binding enp5s0f0 and enp5s0f1 into bond0 and bridged to br0.
  • KVM Virtual Machine Provisioning: Scripted virt-install commands configuring CPU topology, VirtIO storage buses, and bridged TAP network interfaces.
  • Squid SSL-Bump Deployment: Compiled Squid 6.14 with OpenSSL support, generated enterprise Root CA keys (squid-ca.crt), and authored strict access control lists (ACLs).
  • Active Directory PKI Push: Packaged squid-ca.crt into an Active Directory Group Policy Object (GPO), distributing it to Trusted Root Certification Authorities across 100+ Windows endpoints.

4. Production Configurations & Parameter Guide

4.1 Netplan LACP & Bridge Configuration (/etc/netplan/01-netcfg.yaml)

# ==============================================================================
# NETPLAN CONFIGURATION: DUAL-10GBE LACP (BOND0) + LINUX BRIDGE (BR0)
# ==============================================================================
network:
  version: 2
  renderer: networkd
  ethernets:
    enp5s0f0:                             # [CHANGEABLE: First physical 10GbE interface name]
      dhcp4: no
    enp5s0f1:                             # [CHANGEABLE: Second physical 10GbE interface name]
      dhcp4: no

  bonds:
    bond0:
      interfaces:
        - enp5s0f0
        - enp5s0f1
      parameters:
        mode: 802.3ad                     # [CRITICAL: IEEE 802.3ad Dynamic Link Aggregation]
        lacp-rate: fast
        transmit-hash-policy: layer2+3
        mii-monitor-interval: 100

  bridges:
    br0:
      interfaces: [bond0]
      addresses:
        - 192.168.10.10/24                # [CHANGEABLE: Hypervisor Static Management IP]
      routes:
        - to: default
          via: 192.168.10.1               # [CHANGEABLE: Core Switch Gateway IP]
      nameservers:
        addresses:
          - 192.168.10.5                  # [CHANGEABLE: Corporate Domain Controller DNS]
          - 8.8.8.8
      parameters:
        stp: false
        forward-delay: 0

4.2 FortiAnalyzer VM Provisioning Script (KVM virt-install)

#!/bin/bash
# ==============================================================================
# KVM VIRT-INSTALL: FORTIANALYZER ENTERPRISE VM PROVISIONING
# ==============================================================================

virt-install \
  --name=FAZ-VM-PROD \
  --vcpus=4,cores=2,threads=2 \
  --ram=16384 \                           # [CHANGEABLE: Allocate 16GB RAM]
  --os-variant=generic \
  --disk path=/var/lib/libvirt/images/faz_system.qcow2,size=20,bus=virtio,format=qcow2 \
  --disk path=/var/lib/libvirt/images/faz_logs.qcow2,size=100,bus=virtio,format=qcow2 \
  --network bridge=br0,model=virtio \     # [CRITICAL: Connects directly to br0 with VirtIO drivers]
  --graphics none \
  --console pty,target_type=serial \
  --import \
  --noautoconsole

4.3 Squid 6.14 SSL-Bump Proxy Configuration (/etc/squid/squid.conf)

# ==============================================================================
# SQUID 6.14 ENTERPRISE SSL-BUMP HTTPS PROXY CONFIGURATION
# ==============================================================================

# Proxy Listening Port with SSL-Bump
http_port 8080 ssl-bump \
  cert=/etc/squid/certs/squid-ca.crt \
  key=/etc/squid/certs/squid-ca.key \
  generate-host-certificates=on \
  dynamic_cert_mem_cache_size=16MB

# SSL Certificate Decryption Steps
sslcrtd_program /usr/lib/squid/security_file_certgen -s /var/lib/squid/ssl_db -M 16MB
acl step1 at_step SslBump1
ssl_bump peek step1
ssl_bump bump all

# Corporate Access Control Lists
acl corporate_network src 192.168.0.0/16
acl blocked_domains dstdomain "/etc/squid/blocked_sites.acl"

http_access deny blocked_domains
http_access allow corporate_network
http_access deny all

5. Forensic Incident Deep-Dives & Remediation

Incident #1: SSH Public Key Permission Denied on Windows Jump Host (Case 16)

Symptom: Remote administrators using Windows PowerShell received Permission denied (publickey) when attempting to SSH into the Ubuntu hypervisor, while password authentication succeeded.
Investigation: Checked OpenSSH daemon logs using journalctl -u ssh.service. Discovered error: Authentication refused: bad ownership or modes for directory /home/sysadmin/.ssh. Windows client had pushed permissions as 0777 during automated provisioning.
Remediation: Enforced strict Linux file permission standards: 

chmod 700 /home/sysadmin/.ssh
chmod 600 /home/sysadmin/.ssh/authorized_keys
chown -R sysadmin:sysadmin /home/sysadmin/.ssh

Verification: Key-based authentication succeeded immediately with zero password prompts.
