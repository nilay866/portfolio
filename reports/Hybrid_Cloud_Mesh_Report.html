1. Executive Summary & Objective

Enterprise workloads transitioning from on-premises datacenters into hybrid public clouds (AWS and GCP) require deterministic, redundant, and automated network connectivity. Historically, organizations used static route-based VPN connections, which required manual route entry updates every time a new subnet was provisioned in AWS or GCP, creating administrative overhead and frequent service blackouts due to routing table desynchronization.

The Architectural Objective: Deploy a fully automated, dynamic multi-cloud mesh linking on-premises manufacturing networks with AWS and GCP VPC environments:

  • Declare cloud resources declaratively using Terraform (HCL) to provision Customer Gateways, Virtual Private Gateways, and route table associations.
  • Establish redundant dual route-based IPsec tunnels between the on-premise FortiGate Core Hub and AWS Virtual Private Gateway, running dynamic BGP peering over link-local /30 subnets (169.254.10.0/30, 169.254.11.0/30).
  • Enable dynamic BGP route propagation into private VPC route tables, eliminating manual static routing entirely.
  • Deploy custom Python automation daemons (isp_failover.py) tracking dual-WAN circuit health and dynamically updating DNS resolution to maintain 99.99% connectivity.

4. Production Configurations & Parameter Guide

4.1 Terraform HCL (aws_vpn.tf)

# ==============================================================================
# TERRAFORM HCL: AWS VPC TO ON-PREMISE FORTIGATE DYNAMIC BGP IPSEC VPN
# ==============================================================================

# 1. On-Premise Customer Gateway (FortiGate Primary WAN)
resource "aws_customer_gateway" "onprem_core" {
  bgp_asn    = 65000                      # [CHANGEABLE: On-Premise FortiGate iBGP AS Number]
  ip_address = "198.51.100.1"             # [CHANGEABLE: Public Static WAN IP of On-Premise FortiGate]
  type       = "ipsec.1"
  tags = {
    Name = "cgw-core-datacenter-primary"
  }
}

# 2. AWS Virtual Private Gateway Attached to VPC
resource "aws_vpn_gateway" "vpc_gw" {
  vpc_id          = "vpc-0a1b2c3d4e5f60718" # [CHANGEABLE: Target AWS Production VPC ID]
  amazon_side_asn = 64512                 # [CHANGEABLE: Amazon Side Autonomous System Number]
  tags = {
    Name = "vgw-prod-mesh-gateway"
  }
}

# 3. Dynamic Route-Based VPN Connection with BGP Peering
resource "aws_vpn_connection" "onprem_to_aws" {
  vpn_gateway_id      = aws_vpn_gateway.vpc_gw.id
  customer_gateway_id = aws_customer_gateway.onprem_core.id
  type                = "ipsec.1"
  static_routes_only  = false             # [CRITICAL: Enables Dynamic BGP Route Propagation]

  tunnel1_inside_cidr = "169.254.10.0/30" # [CHANGEABLE: Link-local BGP peering subnet for Tunnel 1]
  tunnel2_inside_cidr = "169.254.11.0/30" # [CHANGEABLE: Link-local BGP peering subnet for Tunnel 2]

  tags = {
    Name = "vpn-core-to-aws-prod"
  }
}

# 4. Enable Dynamic Route Propagation into VPC Route Tables
resource "aws_vpn_gateway_route_propagation" "private_routes" {
  vpn_gateway_id = aws_vpn_gateway.vpc_gw.id
  route_table_id = "rtb-01a2b3c4d5e6f7g8h"
}

4.2 On-Premise FortiGate Configuration for AWS BGP Peering

# ==============================================================================
# ON-PREMISE FORTIGATE-1000F CLI: AWS BGP PEERING
# ==============================================================================

# Tunnel 1 Interface IP
config system interface
    edit "AWS_TUN1"
        set ip 169.254.10.2 255.255.255.252
        set remote-ip 169.254.10.1 255.255.255.252
        set allowaccess ping
        set tcp-mss 1379                  # [CRITICAL: Clamp TCP MSS to prevent packet fragmentation]
    next
end

# Dynamic BGP Peering with AWS VGW
config router bgp
    config neighbor
        edit "169.254.10.1"
            set remote-as 64512           # [CHANGEABLE: AWS Amazon Side ASN]
            set soft-reconfiguration enable
            set capability-graceful-restart enable
        next
    end
    config network
        edit 1
            set prefix 10.0.0.0 255.255.0.0 # [CHANGEABLE: On-Premise Subnet Advertised to AWS]
        next
    end
end

5. Forensic Incident Deep-Dives & Remediation

Incident: Large Packet SSH Stalls & TCP Retransmission across AWS Tunnel

Symptom: ICMP ping between on-premises jump hosts and AWS EC2 instances succeeded with 18ms latency, but large SSH sessions and database file transfers hung during initial key exchange or bulk data delivery.
Investigation: Executed packet sniffer diagnose sniffer packet AWS_TUN1 'tcp and port 22' 4 0 l. Discovered IP packet fragmentation flags with Don't Fragment (DF) bit set on 1500-byte packets. AWS IPsec encapsulation added 56 bytes of overhead, breaching the MTU.
Remediation: Applied TCP MSS clamping on the tunnel interface: 

config system interface
    edit "AWS_TUN1"
        set tcp-mss 1379
    next
end

Verification: TCP SYN packets were automatically clamped to MSS 1379; large file transfers and database synchronizations achieved 100% reliability with zero packet drops.
