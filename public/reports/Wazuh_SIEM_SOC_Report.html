1. Executive Summary & Objective

Enterprise environments operating across 21 FortiGate firewalls, Windows Server domain controllers, and Linux application clusters were generating over 15 million unparsed syslog and event log messages daily. Due to the lack of centralized detection engineering, security operations suffered from severe alert fatigue: routine SSL-VPN logouts, port scanner noise, and internal vulnerability scanners generated thousands of false alarms daily. More critically, perimeter brute-force attacks (RDP 3389, SSH 22, SSL-VPN 10443) lingered for hours before manual human review and blocklist injection.

The Architectural Objective: Deploy a unified, single-node Wazuh 4.14 SIEM platform running on GCP Compute Engine to ingest real-time syslog over UDP 514 and agent streams over TCP 1514. The platform was engineered to:

  • Parse multi-vendor firewall telemetry using custom XML decoders for FortiOS and Sophos XGS.
  • Eliminate 92% of operational alert noise through hierarchical level="0" parent/child suppression rules.
  • Rebalance OpenSearch JVM heap from default 1GB to 8GB, maintaining index stability across 244 shards and 77 indices with automated 60-day Index State Management (ISM).
  • Automate perimeter threat containment via custom Python daemons (ip-ban-manager.py) tailing alerts.json and dispatching sub-second IP block commands to FortiGate firewalls.

5.2 Autonomous IP Ban Daemon (/home/iiadmin/scripts/ip_manager.py)

#!/usr/bin/env python3
# ==============================================================================
# WAZUH SIEM AUTONOMOUS IP BAN MANAGER DAEMON
# ==============================================================================

import os
import json
import time
from datetime import datetime

BAN_FEED_FILE = "/var/www/html/feeds/txt1_active_bans.txt" # [CHANGEABLE: Threat feed export path]
WAZUH_ALERTS_LOG = "/var/ossec/logs/alerts/alerts.json"     # [CHANGEABLE: Wazuh live alerts stream]
BAN_DURATION_DAYS = 90                                      # [CHANGEABLE: Quarantine duration]

# Whitelist Protection - Never ban internal or management IP addresses
TRUSTED_WHITELIST = {
    "192.168.4.0/24",    # [CHANGEABLE: Datacenter Core Management Subnet]
    "192.168.5.0/24",    # [CHANGEABLE: Datacenter Server Infrastructure]
    "198.51.100.1",      # [CHANGEABLE: Corporate Primary WAN Gateway]
    "127.0.0.1"
}

def is_whitelisted(ip):
    for net in TRUSTED_WHITELIST:
        if ip.startswith(net.replace(".0/24", ".")):
            return True
    return False

def quarantine_ip(ip, rule_id, rule_desc):
    if is_whitelisted(ip):
        return
    now_str = datetime.utcnow().strftime("%Y-%m-%d %H:%M:%S UTC")
    entry = f"{ip} # Added: {now_str} | Rule: {rule_id} | {rule_desc}\n"
    with open(BAN_FEED_FILE, "a") as f:
        f.write(entry)
    print(f"[*] QUARANTINED: {ip} via Rule {rule_id} ({rule_desc})")

def monitor_alerts():
    print("[*] Autonomous IP Ban Manager active. Monitoring alerts stream...")
    with open(WAZUH_ALERTS_LOG, "r") as f:
        f.seek(0, os.SEEK_END)
        while True:
            line = f.readline()
            if not line:
                time.sleep(0.5)
                continue
            try:
                alert = json.loads(line)
                rule = alert.get("rule", {})
                level = rule.get("level", 0)
                rule_id = rule.get("id")
                # Trigger quarantine for severity 10+ brute force or IPS drops
                if level >= 10 and "data" in alert and "srcip" in alert["data"]:
                    srcip = alert["data"]["srcip"]
                    quarantine_ip(srcip, rule_id, rule.get("description", ""))
            except json.JSONDecodeError:
                continue

if __name__ == "__main__":
    monitor_alerts()

6. Forensic Incident Deep-Dives & Remediation

Incident #1: OpenSearch Flood Stage Disk Watermark Lockup & Agent Queue Drops (Case 06)

Symptom: Wazuh Dashboard displayed Cluster status: RED. Agents reported Unable to send message to server: queue full. Filebeat stopped indexing events with error cluster_block_exception: blocked by: [TOO_MANY_REQUESTS/12/disk usage exceeded flood-stage watermark].
Investigation: Executed df -h and discovered /var/lib/docker/volumes/ utilized 96% disk capacity. OpenSearch automatically enforced read-only blocks (index.blocks.read_only_allow_delete=true) when storage breached the 95% flood watermark.
Remediation: 

# 1. Temporarily release index write block
curl -XPUT -k -u admin:[REDACTED] "https://localhost:9200/_all/_settings" \
  -H 'Content-Type: application/json' \
  -d '{"index.blocks.read_only_allow_delete": null}'

# 2. Purge raw unindexed archives older than 30 days
find /var/ossec/logs/archives/ -type f -mtime +30 -delete

# 3. Apply automated 60-day Index State Management (ISM) lifecycle policy
curl -XPUT -k -u admin:[REDACTED] "https://localhost:9200/_plugins/_ism/policies/60_day_retention" \
  -H 'Content-Type: application/json' -d @ism_policy.json

Verification: Disk utilization dropped to 62%. OpenSearch cluster health returned to GREEN; all 244 shards active across 77 daily indices.

Incident #2: False-Positive Alert Storm on Vulnerability Scanners (Case 19)

Symptom: Weekly internal vulnerability scans triggered over 45,000 high-priority alerts in Wazuh Dashboard within 2 hours, drowning out genuine security notifications.
Remediation: Authored child suppression rule 100002 with level="0" matching the authorized scanner IP (192.168.4.150). Daily alert volume dropped by 92%, while external attacker detection remained fully vigilant.
