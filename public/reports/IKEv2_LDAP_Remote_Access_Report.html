1. Executive Summary & Objective

Engineering and corporate management staff requiring remote access to internal SAP ERP servers and production databases needed a high-performance, cryptographic dial-up solution that did not rely on local firewall user accounts. Storing credentials locally on perimeter firewalls introduced password synchronization divergence and security compliance risks.

The Architectural Objective: Deploy an enterprise IKEv2 Dial-Up VPN interface on the perimeter FortiGate integrated with centralized Active Directory Domain Services via LDAP. When mobile clients initiate IKEv2 tunnels via FortiClient, credentials are authenticated directly against corporate Domain Controllers using EAP-TTLS (Extensible Authentication Protocol - Tunneled Transport Layer Security), and outbound packets are translated to local branch IPs via SNAT pools to avoid cross-mesh routing churn.

3. Production FortiOS CLI Configurations & FortiClient XML

3.1 FortiOS LDAP & IKEv2 Dial-Up Configuration

# ==============================================================================
# FORTIOS 7.4 CLI: ACTIVE DIRECTORY LDAP SERVER & IKEV2 DIAL-UP VPN
# ==============================================================================

# 1. Active Directory LDAP Server Profile
config user ldap
    edit "CORP_AD_LDAP"
        set server "192.168.10.5"               # [CHANGEABLE: Primary Domain Controller IP]
        set cnid "sAMAccountName"
        set dn "DC=integratedinfosec,DC=com"    # [CHANGEABLE: Active Directory Base DN]
        set type regular
        set username "CN=svc_vpn,OU=ServiceAccounts,DC=integratedinfosec,DC=com"
        set password "[REDACTED SECRET]"
        set port 389
    next
end

# 2. Remote User Group
config user group
    edit "AD_VPN_Users"
        set member "CORP_AD_LDAP"
    next
end

# 3. IKEv2 Dial-Up Phase 1 Interface
config vpn ipsec phase1-interface
    edit "IKEV2_DIALUP"
        set type dynamic
        set interface "wan1"
        set ike-version 2
        set proposal aes256-gcm aes128-gcm
        set dhgrp 14 19
        set peertype any
        set mode-cfg enable
        set ipv4-start-ip 10.212.134.10
        set ipv4-end-ip 10.212.134.200
        set ipv4-netmask 255.255.255.0
        set ipv4-dns-server1 192.168.10.5
        set authmethod-remote eap
        set eap-user-group "AD_VPN_Users"
    next
end

        </proposals>
      </connection>
    </connections>
  </ipsecvpn>
</vpn>

4. Forensic Incident Deep-Dive & Remediation

Incident: EAP Password Authentication Error for Active Directory Users (Case 04)

Symptom: Local firewall users authenticated successfully over IKEv2, but Active Directory domain accounts failed immediately with error EAP authentication error: user credential rejected.
Investigation: Executed diagnose debug application ike -1 and diagnose debug application fnbamd -1. Discovered that default FortiClient installations attempted EAP-MSCHAPv2, which Active Directory LDAP rejected because plain LDAP does not support MSCHAPv2 challenge handshakes without a RADIUS/NPS server.
Remediation: Configured FortiClient XML profiles to enforce <eap_method>2</eap_method> (EAP-TTLS), which securely tunnels PAP authentication inside a TLS tunnel directly to the LDAP daemon. Authentication success rate immediately reached 100%.
